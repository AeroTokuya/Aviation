# HeliNav — VFR ヘリコプター ナビゲーション (PWA)

ヘリコプター操縦士向けの **無料・軽量・オフライン対応** の VFR ナビゲーション
ウェブアプリ (PWA) です。iPad / iPhone をコックピットに設置しての使用を想定し、
**大きな表示・少ないタップ数** で操作できるよう設計しています。

> ⚠️ **重要（免責）**: 本アプリは**参考情報**を提供するものです。収録データには
> 概略・未検証のものを含みます。飛行前ブリーフィング・航空図・**AIP Japan**・
> NOTAM 等の**公式情報で必ず確認**し、最終的な運航判断はパイロットが行って
> ください。運航用の航法計器・認証された EFB の代替にはなりません。

## 要件との対応

Notion 要件定義（ヘリコプター操縦士向けナビゲーションアプリ）に対応:

| 要件 | 実装 |
|---|---|
| VFR メイン（IFR は将来） | VFR 前提の地図・ルート機能 |
| 無料で軽量な動作 | 依存は Leaflet のみ・ビルド不要の静的サイト |
| Web ブラウザ / PWA | `manifest` + Service Worker でホーム画面追加・スタンドアロン起動 |
| オフライン動作（必須） | アプリ本体・データ・閲覧タイルをキャッシュ、エリア一括保存 |
| 無料 API・オープンデータ | OpenStreetMap タイル + OSM/公開データの GeoJSON |
| 飛行場・VOR 表示 | `airports` / `navaids` レイヤー |
| ルート・ウェイポイント・フィックス | タップでルート作成、区間ごとの磁方位・距離・ETA |
| ドクターヘリ基地病院 | `heliports` レイヤー（病院＋公共ヘリポート） |
| 送電線情報 | `hazards` レイヤー（サンプル＋OSM から範囲取得） |
| iPad/iPhone・大画面・少タップ | 大きなタッチ FAB / レイヤーボタン、昼夜切替 |

## 使い方（起動）

ビルド不要です。静的ファイルを配信するだけで動きます。

```bash
cd webapp
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

Service Worker（オフライン機能）は `https://` または `localhost` でのみ有効です。
iPad/iPhone では Safari で開き、**共有 → ホーム画面に追加** でフルスクリーンの
アプリとして起動できます。

## 主な機能

- **地図**: OpenStreetMap。昼/夜モード（夜はタイルを減光し暗順応を保持）。
- **レイヤー切替**（左の大ボタン）: 空港 / ヘリ・病院 / VOR / 送電線 / ルート。
- **施設情報**: マーカーをタップ → 識別・標高・滑走路長・座標、現在地からの
  距離・真/磁方位を表示。「ルートに追加」「ダイレクト」。
- **ルート作成**: `✚` でルートモード → 地図タップでウェイポイント追加。
  区間ごとに **磁方位・距離(NM)・ETA**、全長を表示。WP はドラッグで移動、
  タップで削除。磁気偏差・地上速度はメニューで設定。
- **現在地**: `◎` で GPS 追従（機首方位に合わせた自機シンボル、対地速度表示）。
- **オフライン保存**: メニュー →「表示エリアをオフライン保存」で現在表示の
  地図タイルを端末にキャッシュ。
- **ハザード取得**: メニュー →「表示範囲のハザード取得」で OSM の送電線
  (`power=line`) を取得しキャッシュ（オンライン時）。
- **データ取込**: メニュー →「GeoJSON を取込」で公式 AIP 等のデータに差し替え。

## データについて

`data/*.geojson` に収録。座標は WGS84。**運用前に必ず公式情報で照合**してください。

空港・ヘリポート・航法無線施設は **[OurAirports](https://ourairports.org/)
（パブリックドメイン）** のデータを基にしています。座標・標高・滑走路・
通信周波数・VOR 周波数は同データに準拠します。

| ファイル | 件数 | 内容 | 出典・精度 |
|---|---:|---|---|
| `airports.geojson` | 286 | 空港・飛行場（ICAO/IATA・種別・標高・滑走路・**TWR/ATIS/GND 等の実通信周波数**・所在） | OurAirports（実測ベース） |
| `heliports.geojson` | 3,036 | ヘリポート（うち **病院ヘリパッド 459**）・東京ヘリポート等 | OurAirports（実測ベース） |
| `navaids.geojson` | 219 | **VOR/VORTAC/VOR-DME/TACAN/NDB**（識別・**周波数**・CH・関連空港） | OurAirports（実測ベース） |
| `powerlines.geojson` | 2 | 送電線ハザード | サンプルのみ（[ハザード取得]で OSM から拡充） |

VOR 系の周波数は MHz、NDB は kHz で表記します（例: 羽田 HME VOR-DME 112.20 MHz）。
公式データをお持ちの場合は [データ取込] から任意の GeoJSON で各レイヤーを
上書きできます（端末の localStorage に保存され次回以降も適用）。

> ℹ️ ヘリポートは 3,000 件超あるため、ズーム 8 未満では非表示、表示範囲内で最大
> 400 件（病院ヘリパッド優先）に間引いて描画します（コックピットでの視認性・軽量化）。

### GeoJSON フォーマット

各 Feature の `properties.type` で種別を判定します（`airport` / `heliport` /
`hospital` / `navaid` / `powerline`）。任意の追加項目:

```jsonc
{ "type": "Feature",
  "properties": {
    "type": "airport", "ident": "RJTT", "iata": "HND",
    "name": "東京国際空港", "elev_ft": 35, "rwy_ft": 12000, "twr": true },
  "geometry": { "type": "Point", "coordinates": [139.7811, 35.5533] } }
```

`meta.dataset`（`airports`/`heliports`/`navaids`/`hazards`）を付けておくと、
取込時に対象レイヤーを自動判定します。

## 既知の制約

- OSM タイル・Overpass API は**公共サービス**です。過度な取得は避け、
  利用ポリシーを尊重してください（本アプリはタイルを 1 回だけ保存）。
- 磁方位は設定した固定磁気偏差（既定 8°W）で近似します。地域差・経年変化は
  反映しません。
- 送電線・障害物レイヤーは網羅的ではありません。低高度飛行の障害物確認は
  必ず航空図・現地情報で行ってください。
- 地形・空域境界・制限区域は本バージョン未対応（今後の拡張候補）。

## 構成

```
webapp/
  index.html              画面
  manifest.webmanifest    PWA マニフェスト
  sw.js                   Service Worker（オフラインキャッシュ）
  css/app.css             スタイル（昼夜テーマ・大タッチ UI）
  js/app.js               地図・ルート・GPS・取込・オフライン処理
  lib/leaflet/            Leaflet 1.9.4（同梱・オフライン可）
  data/*.geojson          空港・ヘリ/病院・VOR・送電線
  icons/                  アプリアイコン
```

地図タイルのみオンライン取得（未キャッシュ時）。それ以外は完全ローカル動作。
