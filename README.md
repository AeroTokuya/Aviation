# HeliWX — ライブカメラ視程・シーリング推定

ヘリコプター操縦士の天候判断を支援するため、ライブカメラの映像から
**視程 (Visibility)** と **シーリング (Ceiling / 雲底高度)** を推定して
地図上に表示するソフトウェアです。

> ⚠️ **免責**: 本ソフトの推定値は参考情報です。METAR/TAF 等の公式気象情報と
> 併用し、最終的な運航判断は必ず操縦士が行ってください。

## 画面

- 地図上に各カメラの**撮影方角がわかる扇形アイコン**を表示
  (色は推定フライトカテゴリ: 緑=VFR / 青=MVFR / 赤=IFR / 紫=LIFR)
- アイコンをクリックすると右パネルに表示:
  - **現在の画像** と **天気がいい時の基準画像**
  - **推定視程** (km) / **推定シーリング** (ft AGL) / **雲量** (FEW/SCT/BKN/OVC)
  - ターゲット (ランドマーク) 別の視認状況テーブル
- 60 秒ごとに自動再解析

## セットアップと起動

```bash
pip install -r requirements.txt

# デモ用の合成画像とカメラ設定を生成 (初回のみ。生成済みのものを同梱)
python3 scripts/generate_demo.py

# サーバ起動
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

ブラウザで http://localhost:8000/ を開きます。

初期設定には次のカメラが含まれます:

- **実在の公開ライブカメラ 7 箇所** (河口湖・御殿場・日本平・さった峠・
  お台場・横浜みなとみらい・湘南): YouTube 常時配信等の映像を
  パネル内で視聴できます (グレーの「映像のみ」アイコン)
- **【デモ】カメラ 4 箇所** (快晴 / 靄 / 濃霧 / 曇天・低シーリング):
  Koschmieder の法則に従って物理的に正確に霞ませた合成画像で、
  視程・シーリング推定のデモと精度確認ができます

```bash
python3 -m pytest tests/   # 推定ロジックの検証テスト
```

## 推定の仕組み

### 視程 — コントラスト減衰 + Koschmieder の法則

各カメラに、距離が既知のランドマーク (山・鉄塔・ビル等) を
**ターゲット**として基準画像上の矩形 (bbox) で登録します。

1. 現在画像と基準画像の各ターゲット領域で、露出正規化した勾配強度
   (コントラスト指標) を計算
2. 空領域の勾配中央値をノイズ床として差し引き、コントラスト比 `r` を算出
3. Koschmieder の法則 `r = exp(-3.912 d / V)` から各ターゲット単独の視程
   `V = 3.912 d / (-ln r)` を求め、中央値で統合
4. 全ターゲットが明瞭なら「最遠ターゲット距離以上」として下限値を報告

### シーリング — 標高既知ターゲットの遮蔽判定

ターゲットに頂部標高 (`elevation_ft_msl`) を設定しておくと、
「霞だけなら見えるはずなのに実測コントラストが大幅に低い」ターゲットを
**雲による遮蔽**と判定し、見えている最高標高と隠れている最低標高の
中間を雲底として AGL で報告します。山頂・稜線には `bbox` を頂部に
絞って設定すると精度が上がります (推定分解能はターゲットの標高間隔に依存)。

雲量は空領域 (`sky_bbox`) の色解析 (低彩度=雲) で 8 分量を推定し、
BKN 未満の場合はその旨を注記します。

### フライトカテゴリ

| カテゴリ | 視程 | シーリング |
|---|---|---|
| VFR (緑) | > 8 km | > 3,000 ft |
| MVFR (青) | 5–8 km | 1,000–3,000 ft |
| IFR (赤) | 1.6–5 km | 500–1,000 ft |
| LIFR (紫) | < 1.6 km | < 500 ft |

## カメラのソース種別

`config/cameras.json` の `source.type` で 4 種類のソースを扱えます:

| type | 内容 | 視程・シーリング推定 |
|---|---|---|
| `url` | 静止画を直接取得できるライブカメラ画像 URL | **可** (基準画像+ターゲット登録後) |
| `youtube` | YouTube ライブ配信 (`video_id` または `channel_id`) | 不可 (パネル内で視聴) |
| `page` | 提供元ページへのリンクのみ | 不可 |
| `local` | リポジトリ内の画像ファイル (デモ用) | 可 |

```jsonc
// YouTube ライブ (video_id は配信が再開されると変わることがある。
// channel_id 指定ならチャンネルの現行ライブに自動追従)
{ "source": { "type": "youtube", "video_id": "XXXXXXXXXXX" } }
{ "source": { "type": "youtube", "channel_id": "UCXXXXXXXXXXXXXXXXXXXXXX" } }
```

### 推定を有効にする手順 (url 型カメラ)

1. ライブカメラページをブラウザの開発者ツール (ネットワークタブ) で開き、
   定期更新される**静止画像の直接 URL** を調べて `source.url` に設定する
2. アプリを起動し、**快晴で遠方までよく見える日**にそのカメラのパネルで
   「現在の画像を晴天時基準画像として保存」ボタンを押す
   (または `POST /api/cameras/{id}/capture_reference`)
3. 基準画像を見ながら、距離・標高が既知のランドマークを `targets` に登録する
   (距離は地図で計測、標高は地形図・建物データから)
4. これで視程・シーリング推定が有効になり、アイコンが
   フライトカテゴリ色に変わります

### 公開カメラ利用時の注意

- 各カメラの映像の権利は提供元にあります。**提供元の利用規約を確認**の上、
  組織内での利用にとどめ、再配信・二次利用はしないでください
  (本アプリは提供元 URL から都度取得して表示するのみで、映像の保存は
  基準画像のワンショットに限られます)
- YouTube の `video_id` は配信の再起動で変わることがあります。
  切れていたらパネルの提供元リンクから新しい ID を確認して更新してください
- 取得間隔は 60 秒キャッシュで礼儀的に抑えています (`app/sources.py`)

## 実際のライブカメラを登録する

`config/cameras.json` を編集します。

```jsonc
{
  "cameras": [
    {
      "id": "my-camera",
      "name": "○○ヘリポート 西向きカメラ",
      "lat": 35.63, "lon": 139.83,
      "heading_deg": 270,          // 撮影方位 (真北 0°, 時計回り)
      "fov_deg": 60,               // 水平画角 → 地図の扇形に反映
      "elevation_ft": 20,          // カメラ設置標高 (MSL)
      "reference_image": "data/reference/my-camera.jpg",
      "source": {                  // 現在画像の取得元
        "type": "url",             // "url" = ライブカメラ, "local" = ファイル
        "url": "https://example.com/livecam/latest.jpg"
      },
      "sky_bbox": [10, 6, 780, 150],   // 純粋な空の領域 (ノイズ床・雲量用)
      "targets": [
        {
          "name": "富士山",
          "distance_km": 95,
          "elevation_ft_msl": 12388,   // 省略可 (シーリング推定に使用)
          "bbox": [80, 233, 140, 87]   // 基準画像上の [x, y, w, h]
        }
      ]
    }
  ]
}
```

運用のコツ:

- **基準画像**は例外的に澄んだ日 (視程 50 km 以上) に撮影したものを使う。
  基準自体が霞んでいると視程を過大評価します。
- **ターゲット**は近距離〜遠距離まで距離を分散させて 4 個以上登録すると
  推定が安定します (視程レンジ = 登録した距離レンジ)。
- **シーリング用**には標高の異なる山・稜線・鉄塔を登録し、bbox を
  頂部に絞る。標高の間隔がそのまま雲底推定の分解能になります。
- カメラの画角・ズーム・向きを変えたら基準画像と bbox を取り直すこと。
- ライブカメラ URL は 60 秒キャッシュされます (`app/sources.py`)。

## 制約・既知の限界

- 夜間・逆光・レンズの水滴/汚れでは推定精度が大きく低下します。
- 降水 (雨・雪) による視程低下は霧と同様に検出されますが区別はしません。
- 雲底がカメラから見える最高ターゲット標高より高い場合は
  「雲遮蔽なし (それ以上は判定不能)」としか言えません。
- 推定視程の上限は最遠ターゲット距離で頭打ちになります (50 km でキャップ)。

## 構成

```
app/            FastAPI サーバ + 推定エンジン
  analysis.py     視程・シーリング・雲量推定 (コア)
  sources.py      画像取得 (ローカル / URL, キャッシュ)
  config.py       cameras.json 読み込み
  main.py         API エンドポイント
static/         フロントエンド (Leaflet 地図, 同梱でオフライン可)
scripts/        デモ画像生成 (generate_demo.py)
config/         カメラ設定 (cameras.json)
data/           基準画像・デモ現在画像
tests/          推定ロジックのテスト
```

地図タイルは OpenStreetMap をオンラインで取得します (それ以外は完全にローカル動作)。
